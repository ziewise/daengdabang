# 06. 댕다방 앱 틀(App Shell) 구조 분석 · 제안

> 작성: 2026-10-10 · 상태: **로컬 검토용 초안**(협업자 미협의 · 커밋 전)
> 범위: 앱(PWA · Android/iOS)을 "앱 전용 화면 + 앱 안에서 여는 쇼핑몰"로 바꾸기 위해
> 사이트 전체 화면 · 공유 데이터 · 화면 틀 · 결제 · 앱 연결 코드를 코드 기준으로 전수 조사한 결과.

---

## 0. 한 줄 결론

**앱 화면을 앱 안에 따로 넣어 두지 말고, 실제 사이트의 `/app/` 아래에 앱 화면을 만들고, PWA와 정식 앱이 모두 그 사이트를 열게 한다.**
그래야 로그인 · 장바구니 · 결제가 하나로 이어지고, 쇼핑몰도 앱 틀(상단바 + 탭바) 안에서 열 수 있다.
로컬 시안은 이 구조로 PWA(웹) 기준으로 먼저 만들어 보여 준다. 정식 앱 설정 · 결제 처리는 협업자와 협의 후.

---

## 1. 지금 구조와 문제

### 1-1. 접속 경로 세 가지

| 경로 | 시작 화면 | 쇼핑 | 로그인 · 장바구니 |
|---|---|---|---|
| 모바일 웹 (daengdabang.com) | 쇼핑몰 홈 `/` | 같은 사이트 | 하나 |
| PWA (홈 화면 설치) | `/app/?source=pwa&shell=4` | 같은 사이트 | 웹과 공유 |
| 정식 앱 (Capacitor, 출시 전) | 앱 안에 넣어 둔 `/app/` (`https://localhost`) | 별도 브라우저 창 / 일부 앱 안 원격 | **웹과 따로** |

정식 앱에 들어 있는 화면(`prepare-native-web.mjs`): `app, auth, chat, legal, my-pet, mypage, offline, pet-lens, petlens, privacy, terms` (용량 상한 40MB, 쇼핑몰 전체는 이미지 때문에 약 1.5GB라 제외).

### 1-2. 확인된 문제 (중요도 순)

1. **로그인 · 장바구니 분리** — 로그인 토큰(`ddb.api.accessToken`), 장바구니 · 회원 정보(`daengdabang.store.v2`)가 모두 브라우저 저장소(localStorage)에 있고 쿠키 · 서버 세션이 없다. 저장소는 주소(도메인)마다 따로라서, 정식 앱(`https://localhost`)과 쇼핑몰(`www.daengdabang.com`)이 서로의 로그인 · 장바구니를 못 본다.
2. **결제가 앱 안에서 끝날 수 없음** — `/cart` · `/checkout` 이 앱 밖 브라우저 창에서 열리고(장바구니 비어 있음), 결제 복귀 주소가 `window.location.origin` 기준이며, 카드사 · 간편결제 앱 호출(안드로이드 `intent://`, iOS 앱 스킴) 처리가 없다. 결제 대기 정보도 sessionStorage 라 창을 넘나들면 사라진다.
3. **상품 상세가 앱 밖으로 열리는 버그** — 앱은 `/products` 로 시작하는 주소만 앱 안에서 여는데, 상품 상세는 `/product/<slug>`(s 없음)라 별도 브라우저 창으로 빠진다.
4. **화면이 들쭉날쭉** — 앱 홈만 앱 디자인, 마이페이지 · 우리 아이 · AI 상담 · 펫렌즈는 사이트 화면 그대로(사이트 헤더 포함), 매일 댕생활 · 댕자랑 · 쇼핑은 별도 브라우저 창.
5. **디자인 변경마다 앱 심사** — 앱 안에 넣어 둔 화면은 고칠 때마다 앱 재빌드 · 스토어 심사가 필요.
6. **소셜 로그인 복귀** — 네이버 · 카카오 · 구글 로그인 후 돌아오는 주소를 서버가 정하는데, 정식 앱에서는 엉뚱한 쪽에 토큰이 저장될 수 있다.

## 2. 앱 틀(App Shell) 구성

### 2-1. 상단바

| 화면 | 왼쪽 | 가운데 | 오른쪽 |
|---|---|---|---|
| 탭 첫 화면(홈 · 쇼핑 · 댕생활 · 우리 아이 · 마이) | 댕다방 심볼 | 탭 이름(홈은 생략) | 검색 · 장바구니(개수 배지) · 펫렌즈 |
| 하위 화면(상품 상세, 주문 내역 등) | 뒤로 | 화면 이름 | 장바구니 |

- 높이는 기존 `--header-height` 변수로 내보내서, 이 값을 쓰는 화면들(상품 탭 고정, 마이페이지 사이드 등)이 그대로 동작하게 한다.
- 상단바에 `backdrop-filter`(흐림)를 쓰면 안쪽 고정 요소의 기준이 바뀌므로, 모달은 지금 `RegionModal` 처럼 body 로 띄운다.

### 2-2. 아래 탭바 (5칸)

| 탭 | 들어가는 화면 | 처리 방식 |
|---|---|---|
| **홈** | `/app/` (인사 · 출근도장 요약 · 댕다방 즐기기 · 바로가기) | 앱 전용 화면(시안 c) |
| **쇼핑** | `/products` · `/category/*` · `/product/*` · `/best` · `/new` · `/brands` · `/brand/*` · `/bundles` · `/bundle/*` · `/promo/*` · `/reviews` · `/cart` · `/checkout*` | 쇼핑몰 화면 그대로 + 앱 틀. 쇼핑 탭 첫 화면은 카테고리 메뉴(`lib/menu-data.ts` `CATEGORY_GROUPS`) + 상품 목록으로 새로 구성하면 좋음 |
| **댕생활** | 출근도장 · 오늘의 돌봄 · 보물 상자 · **댕자랑**(`/daeng-showcase`) · 굿즈 공모전 배너 | 앱 전용 화면 새로(`/app/daily/`). 기존 `/treasure-mine` 은 웹용으로 유지 |

| **마이** | `/mypage/*`(주문 · 배송지 · 결제수단 · 정보 · 추천 설정 · 탈퇴) · 언어/국가(RegionModal) · 고객센터(`CS_LINKS`: FAQ · 공지 · 1:1 문의 · 교환/반품) · 약관 | 마이페이지 화면 그대로 + 앱 틀. 마이 탭 첫 화면만 앱식 메뉴 목록으로 정리 |

### 2-4. 앱 틀 안에서 숨길 사이트 요소

- 사이트 헤더 전체(로고 · 앱 홈 버튼 · 지구본 · 햄버거 · 펫렌즈 50px 버튼, 상품 상세의 투명 헤더 · 뒤로 버튼) → 앱 상단바로 대체

## 4. 앱과 쇼핑몰이 반드시 공유해야 하는 것

모두 브라우저 저장소(localStorage/sessionStorage)에 있어 **같은 주소(도메인)에서 열려야만** 공유된다.

| 항목 | 저장 위치(키) | 끊기면 생기는 일 |
|---|---|---|
| 로그인 토큰 | `ddb.api.accessToken` | 앱에선 로그인, 쇼핑에선 로그아웃 |
| 회원 · 장바구니 · 찜 · 주문 | `daengdabang.store.v2` | 장바구니가 비어 보임, 로그아웃이 한쪽만 됨 |
| 헤더 로그인 표시 | `daengdabang_logged_in` | 로그인 버튼 표시가 엇갈림 |
| 결제 대기 정보 | sessionStorage `ddb.toss.test.pending.v1.<주문번호>` | 결제 후 장바구니에서 결제한 상품이 안 지워짐 |
| 회원가입 · 소셜가입 이어가기 | sessionStorage `ddb.signup.*Resume.v1`, `ddb.petlens.signupDraft.v1` | 가입 도중 정보 사라짐 |
| 언어 | `daengdabang.locale` | 앱과 쇼핑 언어가 다름 |
| 국가 → 통화 | `daengdabang.country` | 가격 표시(원/달러)가 다름 |
| 산책 강아지 설정 | `ddb.petCompanion.v1` | 설정 초기화 |
| 착용샷(try-on) 진행 | sessionStorage `ddb.tryon.background.v2` 등 | 진행 중 작업이 안 보임 |
| AI 상담 대화 이어가기 | `DDB_SHOP_CHAT_CONVERSATION_V1:*` | 대화가 처음부터 |
| 굿즈 공모전 비회원 인증 | `ddb.goodsContest.guestToken*` | 이메일 재인증 |
| 방문 · 유입 분석 | `ddb.analytics.*` | 한 사람이 두 명으로 집계, 유입 경로 끊김 |
| 옛 반려견 목록 · 대기 결과 | `daengdabang_pets`, `daengdabang_pet_pending` | 로그인 시 옮겨지지 않음 |

→ **PWA(웹)는 이미 같은 주소라 그대로 공유된다.** 정식 앱만 문제이며, 해결책은 정식 앱이 `www.daengdabang.com` 을 직접 여는 것(1순위). 대안(토큰 넘겨주기 딥링크, 서버 장바구니)은 일이 크고 빈틈이 많다.

## 5. 정식 앱 전환 때 처리할 것 (협업자 협의 필요)

1. **앱이 사이트를 열게 변경** — `capacitor.config.ts` 에 서버 주소 지정(앱 안 묶음 → 사이트 직접 열기), 오프라인 화면은 유지. 심사 대비: 앱 전용 탭 구성 · 카메라/마이크 분석 · 푸시 알림으로 "웹 포장 앱" 거절 기준을 넘긴다.
2. **앱 안에서 열 주소 목록 정리** — `NativeAppBridge` 의 `/products` 오타성 규칙(`/product/` 누락) 수정, 쇼핑 · 장바구니 · 결제를 앱 안에서 열기, `router.push` 이동도 처리.
3. **결제(토스페이먼츠)** — 토스 · 카드사 · 간편결제 주소 허용, 안드로이드 `intent://` 처리와 `<queries>`, iOS `LSApplicationQueriesSchemes`, 복귀 주소를 `https://www.daengdabang.com` 기준으로.
4. **소셜 로그인 복귀** — 앱에서 시작한 로그인이 앱으로 돌아오게(서버 `return_to` 처리).
5. **서버 확인** — API(`api.daengdabang.com`) 허용 출처(CORS), 토스 복귀 주소 허용 목록.
6. **푸시 알림** — 출근도장 알림(매일 들어오는 이유).
7. **테스트 수정** — `tests/pwa-installation.test.mjs` 가 `ConditionalChrome` · `InstalledAppHomeButton` · `MobilePanel` 문구를 검사하므로 함께 수정.
