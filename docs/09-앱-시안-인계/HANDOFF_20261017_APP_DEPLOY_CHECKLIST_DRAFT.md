# 앱 시안 배포 체크리스트 (2026-10-17, 초안)

스티커북 앱 시안(`local/sticker-mockup`)을 운영(`origin/main` → Cloudflare 빌드 → daengdabang.com)에 올리기 전 · 올린 직후에 할 일.
아이폰은 Mac 없이 앱을 만들 수 없고, 댕다방 서버(API)가 운영 주소와 `localhost` 요청만 받기 때문에
**실기기(아이폰) 확인은 배포 뒤 "홈 화면에 추가"한 설치 앱(PWA)으로** 한다(사용자 결정 2026-10-17).

자세한 작업 기록은 `HANDOFF_20261015_APP_STICKER_MOCKUP_CURRENT.md`, 버튼 점검은 `버튼대조표_20261017.md`.

## 2. 웹 방문자에게 바뀌는 것 — 없음(근거)

- 앱 모양(앱 상단바 · 탭바 · 스티커북)은 **설치한 앱에서만** 켜진다: 네이티브 앱(APK) 또는 홈 화면에 추가한 앱(PWA). 일반 브라우저(PC · 모바일)는 어느 주소든 웹 그대로.
- 개발 서버 전용 시안 확인 장치(`?app=1`, `/app/` 주소로 앱 모양 켜기)는 운영 빌드에서 꺼짐(`process.env.NODE_ENV`).
- 앱 전용 CSS 는 전부 `html.ddb-app-mode` 아래에서만 적용.
- 협업자 파일의 앱 전용 버튼 · 틀은 웹에서 보이지 않음(`?app=0` 로 화면마다 확인).
- 확인 결과(운영 빌드 결과물로): 아래 "3. 배포 전 최종 점검" 참고.

## 5. 배포 순서

1. **직전 확인**: `git fetch --prune` → `origin/main` 에 새 커밋이 있으면 시안 브랜치에 합치고 테스트 · 빌드 다시.
2. **올리기**(사용자 허락 후): `git push origin local/sticker-mockup:main`
   - 운영 main 이 시안 브랜치에 이미 다 들어 있어 덧붙이기(fast-forward)로 올라감 — 강제 푸시 없음.
   - `origin` 푸시는 ziewise(운영) + ziewisemin(백업) 두 곳. ziewisemin 이 rejected 로 나오는 건 정상(무시).
3. **Cloudflare 빌드 확인** — 빌드 성공 · 배포 완료까지.
4. **되돌리기(문제 있을 때)**: Cloudflare 대시보드에서 이전 배포로 되돌리기(가장 빠름) → 그 뒤 원인 고쳐 다시 올림. GitHub main 을 강제로 되돌리는 것은 협업자와 상의 후.
